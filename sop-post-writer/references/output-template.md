# 分层交付模板

## 文件隔离

建议分别交付 `作者完整版.md`、`作者后台运营策略.md`、`公开稿_小红书.md`、`公开稿_公众号.md`；仅生成用户要求的平台。需要出售资料时另做 `付费读者教程.md`，不要直接把含后台策略的作者档案拿去卖。

作者完整版写足细节，公开稿做选择性精简，付费读者教程保留完整执行路径。作者后台文件可包含发布节奏、免费/付费切分、转化设计和编辑备注；这些不是公开正文。

## 作者完整版的图文 SOP 骨架

以下是默认骨架，按选题合并或删减，不凑章节。

1. **封面和一句实操目标**：系列名、期号、产品、方案/实测状态。
2. **这门生意到底卖什么**：主客群、场景、第一款 SKU、差异化、暂时不做什么。
3. **完整流程图**：标明 Agent、人工、外包三类责任。
4. **工具与最低配置**：已有设备优先；无机器时说明外包和小批量选项。
5. **逐步生产 SOP**：每步输入、操作、输出、验收、失败时处理。
6. **Agent 提示词**：选品研究、设计转译、核价、分渠道内容、订单整理。不要让订单助手自行承诺交期或退款。
7. **单件经济模型**：实际数/假设数分列，列人工时间和返工，附售价敏感性；算到收入目标所需单量和工时，不伪装成收入预测。
8. **内容分发**：每个平台给可复制稿及图像/镜头 demo。
9. **销售与履约**：询单、需求确认、报价、确认稿、出货及售后话术。不得笼统宣称“定制一律不退”。
10. **7 天最小验证**：先原型和真实报价，再小规模内容测试；指标、预算上限和停止条件清楚。预算未经授权不实际花。
11. **GitHub 技能表**：步骤、精确链接、用途、输入输出、证据级别、验证结果、限制、许可证状态。
12. **X 可发布长帖**：成品/任务钩子 → 第一步 → 核心流程 → 单件账 → 渠道打法 → 验收提醒 → 收藏型清单。若未经营，开头写“我拆了一套方案”，而非“我做到了”。

## 公开渠道内容包

以下是向读者发布的成品，不是教作者如何运营的说明。为每篇选一个具体任务，开头说明将做出什么，直接给少量关键步骤、一个真实或标注为示例的例子和实用清单。不以“项目是否值得做”的评测框架组织公开稿。全文不出现“本页用于引流”等制作话术。长度以平台阅读方式和信息必要性决定，不强制填满字数。

### 闲鱼
- 3 个 SKU 标题与规格、真实材质、尺寸、价格对应的内容、制作时间和可定制范围。
- 图片：主图、尺寸、结构细节、选项、交付清单。没有实物时只做“上架图结构 demo”，不能冒充可销售实拍。
- 咨询话术先问尺寸、用途、时间、图案权利，再报价。

### 小红书
- 重封面吸引、分页图解和收藏价值；一页一个关键结论，结尾附可保存的执行清单。
- 选题至少覆盖成品对比、制作过程、送礼场景三个角度。
- 一套轮播可用：封面 → 产品结构 → 从照片到图纸 → 成本假设 → 交付 → 验证计划。
- 提供正文与站内行动引导；不承诺跨平台导流不会违规。

### 公众号
- 将同一 SOP 改写为连贯案例：实操目标 → 准备清单 → 按顺序操作 → 示例 → 验收与交付。公开版教读者完成一件事，不堆入作者完整版全部细节；成本和限制随相关步骤说明。
- 保留必要流程图、精选可复制提示词和实用清单；详尽参数、排错树和全套模板可留给付费教程，但公开稿本身必须有用。
- 引入案例时标明实际执行、方案示例和待验证部分，保持与其他平台相同的事实和数字。
- 长文用小标题、短段落和图注建立阅读节奏；不要将小红书分页截图直接堆成整篇文章。

### 抖音
- 按过程、产品、经营拆解分内容栏目，不需要先建多个账号。
- 给 15–30 秒脚本：时间段、画面、字幕、旁白、所需真实素材。
- 提供竖屏分镜样图，显著写“脚本/AI 画面示意”；不得把静态分镜说成已生成视频。

## 建议交付目录

```text
选题名称/
  SOP.md
  images/
    cover.png
    workflow.png
    xiaohongshu-demo.png
    douyin-demo.png
```

这是目录约定，不是要求交付空文件。缺图则明确缺口，不留假图片链接。平台政策和价格若未经当次核对，标为发布前待确认，不编造最新规则。

## 付费资料与备份包

作者完整版须包含输入准备、逐步操作、参数解释、完整提示词、输入输出例子、排错、人工接管、验收、交付和来源证据。内容优先不代表内容可以粗糙，未实测不代表可假称实测。

付费读者版保留可执行细节，去除作者获客策略、编辑备注和对 AI 的制作命令。可按请求整理目录、版本号、适用条件、PDF 与原始 Markdown/素材包。PDF 需渲染检查图文和分页；网盘分享/上架/销售另按授权操作。不要直接打包第三方开源技能全文出售而不核对许可。

交付检查：公开稿是否独立有用？完整版是否真能逐步照做？付费稿是否没有作者后台内容？几个版本是否事实一致？是否有夸大收益或未标注的虚构经历？

## 开篇与结构纠偏

不采用：“这门生意值得做吗？我从市场、风险、优缺点评估一下。”
采用：“把一张宠物照片做成拼豆钥匙扣，可以按这条流程准备：先定尺寸和色数，再生成图纸、确认背板，最后打样和核价。下面从第一步开始。”

这是操作指南示例，不代表已经完成生产或获得订单。主线是做法，分析仅服务具体步骤。作者详细版继续保留背景研究、完整参数、排错与证据，不能因公开稿直接而删去这些内容。
