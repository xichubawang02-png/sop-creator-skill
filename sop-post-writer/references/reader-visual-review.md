# 读者视角视觉审阅

审阅对象是读者最终会看到的版面，而非作者脑中的设计。用实际截图、HTML 渲染或 PDF 页面检查，不只读 Markdown 源码。若只有源码，明确仅完成内容/结构检查，不能宣称视觉验收通过。

## 准备证据

- 记录被审文件及版本、平台、渲染方式、视口宽高或 PDF 页码。
- 公众号 HTML 至少检查首屏和中后段的代表位置；可用约 390 px 宽的移动视口模拟，再看长提示词、图片与结尾。该宽度是模拟值，不代表用户手机。
- 小红书看每张成图，检查封面和连续滑读效果。用手机近似显示尺寸观察，但不得称为真机实测。
- 公众号编辑器粘贴后可能改变 CSS；只有源 HTML 的浏览器截图时，标为“HTML 浏览器模拟”，不能声称已验证公众号真实发布效果。
- 记录尚未检查的设备、编辑器或页面。不能凭缺乏证据推断文字溢出、图片缺失或加载成功。

## 检查什么

1. **首屏**：能否迅速看懂主题、具体场景或要完成的任务？大标题是否挤占内容？关键信息是否被装饰和免责声明淹没？必要风险提示仍须可见。
2. **文字密度和图片数量**：哪里出现连续长段、过小字体、重复列表？图太少是否让操作难懂？不要机械补图；指出哪个步骤需要示例、过程或结果图。
3. **图文节奏**：文字是否铺得过长才出现图？相邻图是否重复？图片是否紧邻对应说明？不为了装饰制造无信息量图片。
4. **小屏阅读**：字、图注、尺寸标注能否读清？表格/提示词是否横向溢出？图片是否缩到无法识别细节？按钮或链接若存在是否有清晰文字？
5. **信息层级**：标题、步骤、正文、提示、图注能否区分？强调是否过量？配色和对比是否使正文难读？
6. **平台适配**：公众号是舒适的 HTML 落地教程；小红书是自然好看的场景分享，不应改造成满屏步骤框图的 PPT。审阅不把两个平台强行改成同一种版式。
7. **真实性与隐私**：概念图/未实测标记能否读到？是否有真实私人信息、假订单或未经许可的素材？确认打码在导出成图中有效。

## 审阅输出

每条意见必须有证据位置、观察到的问题、对读者的影响、具体修改方案和优先级。例如：

| 位置/证据 | 观察 | 具体修改 | 优先级 |
|---|---|---|---|
| HTML 模拟 390×844 首屏，标题下方 | 引言占据余下屏幕，第一步不可见 | 引言缩成两句，把工具清单移入第一步旁边 | 高 |
| 轮播第 3 图，下半部 | 图注在缩小显示时难辨 | 去掉重复句、放大核心图注，细节移正文 | 中 |

上述只是格式示例，不是任何实际文件的审阅结论。真实报告只填写自己看见的问题。不要用“更高级”“更舒服”代替修改建议。

## 修改与复检

优先修会阻碍阅读的溢出、裁切、过密、缺关键图和平台错配。直接执行已授权范围内的排版修订，再用相同视口/页码重新渲染查看对应位置。保留修前/修后证据或可比描述。未修项说明原因，不假装全部通过。

交付时说明：实际检查方式、范围、已修问题、剩余限制。推荐措辞：“已用 390 px 宽浏览器视口检查 HTML 首屏及步骤段落，尚未在公众号编辑器或真机验证。”只有确实进行了相应检查才可使用。
