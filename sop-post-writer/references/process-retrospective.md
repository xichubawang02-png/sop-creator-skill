# 首期复盘：从一个点子变成系列化图文 SOP

这是根据用户逐步提出的要求整理的过程，不是经营成绩复盘。

## 需求如何演变

1. **起点：拼豆钥匙扣 + 3D 打印能不能 Agent 化。** 不只回答能不能，先拆数字工作和实体操作，避免“一键制造”的错觉。
2. **用户补充商业化。** 增加目标客户、SKU、推销、闲鱼/小红书/抖音及具体引流内容，不停在技术流程。
3. **用户明确只需写好 SOP，不必完美执行，交 `.md`。** 以内容完成度为终点；研究和最小样例支持写作，不以开店、成交或量产作为交付前提。
4. **用户要全篇排版和穿插配图。** 从纯文字升级为封面、流程和渠道 demo；图片是信息，不只是装饰。
5. **用户提出强冲击封面和笔刷下划线。** 保留商业/赛博视觉，标题可斜；但不能让视觉强度变成收益承诺。
6. **系列名定为《闲鱼月入五位数？拆解一门小生意》。** 问号是关键，标题由断言变成待拆解问题，配上未验证标记。
7. **从小红书图扩展到抖音矩阵视频样图。** 为不同渠道设计不同阅读/观看方式；静态分镜不冒充成片；该打码的地方打码。
8. **用户要整个流程可用的 GitHub skill，并希望跑一跑。** 建立精确源链接、步骤映射和证据分级，允许低风险最小验证，而非默认安装并执行所有外部代码。
9. **用户要求生成《SOP 帖子写手》技能。** 固化的是需求递进、取舍、模板和校验规则，不是把本期产品硬编码成所有选题的答案。

10. **用户进一步明确同一 SOP 多平台适配。** 小红书突出封面、分页图解与收藏清单；公众号承载完整案例、流程及提示词。复用底层事实，重写各平台的信息组织，而不是一稿原样群发。

## 哪些坑需要留下

- 视觉曾出现与产品不符的毛线质感、未经授权的知名形象或易误读为真实成绩的数字。应淘汰，不因画面好看而接受。
- 技能名称和路径会变；必须打开精确文件核对。泛用 pixel-art 不能冒充拼豆专用工程工具。
- “按技能说明写出样例”和“运行第三方代码”是两种证据。OpenSCAD 导出成功也不等于成品强度合格。
- 打印结构以标准底座、可变图案起步更容易控制成本；具体间隙和孔位仍要量实物。
- 不能只讲 AI 省了什么，要写清人工熨烫、启动设备、质检、包装和售后承担什么。
- 收入目标必须连着单量、工时、成本与需求假设；没有真实订单就不写亲身赚钱经历。
- Markdown 只是文本文件，图片必须随包带走。相对链接 + ZIP 是图文交付的一部分。

## 下一期可复用的提示

“请使用 SOP 帖子写手，将【选题】写成《闲鱼月入五位数？拆解一门小生意》的下一期。先给商业判断与人机边界，写完整生产/获客/履约 SOP，制作封面、小红书轮播和抖音分镜 demo；列 GitHub skill 精确来源和实际验证程度。不要编造成交或收入，不要实际发布、安装或开店。交付 Markdown 与带图片的 ZIP。”

当前是原始版本的流程沉淀。之后以实际文章质量和读者反馈迭代，不声称这套技能已经验证变现效果。

## 后续关键纠正：不要混淆作者和读者

用户明确：作者后台的运营策略与面向读者的发布成品必须隔离。免费内容是有价值的精简拆解，保姆级详细步骤可以留付费版。小红书和公众号要按阅读方式调整长度与插图，避免冗余和运营元叙述。

随后补充：精简只针对公开引流版。作者版必须完整细致、保姆级，作为备份并可整理为闲鱼出售的资料，支持 PDF/网盘打包。由此采用作者完整版、后台策略、公开稿、付费读者教程的分层，而不是把所有文档统一缩短。仍然不虚构经历、收益或验证结果，也不自动发布、上架或创建公开网盘链接。
